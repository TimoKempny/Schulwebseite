Klassendiagramm (UML)

CodeBeschreibung
 
class Auto {
    -String kennzeichen
    +int baujahr
    +fahren(int km) void
}
Klasse mit Attributen und Methoden. Rückgabetyp steht hinter der Klammer.
+ - # ~Sichtbarkeit: + public, - private, # protected, ~ package
+getAnzahl()$ int
+zeichnen()* void		$ = statisch (unterstrichen) · * = abstrakt (kursiv)
<<interface>> Form
<<abstract>>		Stereotyp, als eigene Zeile oder innerhalb der Klasse
Fahrzeug <|-- AutoVererbung – Auto erbt von Fahrzeug (Spitze zeigt zur Oberklasse)
Form <|.. KreisRealisierung – Kreis implementiert das Interface Form
Haus *-- RaumKomposition (gefüllte Raute) – Raum existiert nicht ohne Haus
Klasse o-- SchuelerAggregation (leere Raute) – Teil kann auch allein existieren
Person --> Auto
A ..> B		Assoziation (gerichtet) · Abhängigkeit (gestrichelt). -- = ungerichtete Assoziation
Person "1" --> "0..*" Auto : besitztMultiplizitäten in Anführungszeichen, Beschriftung nach dem Doppelpunkt

ER-Diagramm

CodeBeschreibung
KUNDE ||--o{ BESTELLUNG : gibt_aufBeziehung mit Kardinalität an beiden Enden und Beschriftung. Ein Kunde gibt null bis viele Bestellungen auf, jede Bestellung gehört zu genau einem Kunden.
||genau eins (1)
|o  o|null oder eins (0..1)
}|  |{eins oder mehr (1..*)
}o  o{null oder mehr (0..*)
--  ..Durchgezogen = identifizierende Beziehung · gestrichelt = nicht identifizierend
KUNDE {
    int kundenNr PK
    string name
    int ortId FK
}
Attribute: Typ Name, dahinter optional PK (Primärschlüssel), FK (Fremdschlüssel), UK (eindeutig)

Notation: Krähenfuß. Beschriftungen mit Leerzeichen in Anführungszeichen setzen: : "gibt auf". Beispiel im Diagramm-Editor öffnen →

    section Planung
        Ideen sammeln :a1, 2026-11-02, 3d
